动效：编排、缓动与连续

动效不是装饰，是讲述变化的语言。本章把 --dur-* 与 --ease-* 两族令牌兑现为可操作的编排规则：每个动效必须服务引导、反馈、解释、连续、愉悦、叙事六者之一；进场慢而退场快；一屏只用一处力；prefers-reduced-motion 下一律给终态而非全关。本章所有演示都可以动手调参。

开物共生
M.1

动效的唯一理由

六个目的 · 服务不了就删掉

多余的动效是负债，不是加分。评审一个动效只问一句：它服务下列哪一个目的？答不上来，删。第二条铁律是「快比慢安全」——大多数 UI 过渡落在 150–300ms；超过 400ms 的非叙事动效会让界面显得迟钝，只有叙事性、展示性动效才可以长。

六目的每个动效在代码评审时都要能指认其一

M.2

缓动是性格 Easing

6 条曲线 · 全站不得出现第七条

缓动曲线决定动效的气质，比时长更影响观感。全站只用下列六条；一屏之内的所有动效共享同一缓动族，界面才像出自同一套物理规则。几乎不用 linear 做位移与淡入——除了无限循环与滚动绑定。指针悬停或点击任一卡片即可播放。

缓动族曲线图为实测贝塞尔控制点，轨道为实时播放悬停播放
--ease-out减速到位
进场、展开。最常用的一条：让人看清新内容从哪里来。
--ease-in果断离开
退场、收起。别让用户等一个他已经决定丢弃的东西。
--ease-standard中性利落
通用过渡与大元素转场；加长时长即「强调」。
--ease-elegant东方从容
品牌时刻与慢过渡：水的隐喻，有重力与惯性，不弹跳。
--ease-spring轻微回锋
弹窗入场与成功反馈。overshoot 控制在 10% 内——书法收笔的回锋，多一分即廉价。
--ease-linear仅循环
只用于无限循环（太极 Loading）与滚动绑定（scrub）。匀速位移看起来机械、廉价。
M.3

时长尺度与进退场不对称

退场 ≈ 进场 × 0.65

进场稍慢、用 ease-out 减速到位，让人看清新内容来自哪；退场更快、用 ease-in 加速离开。二者的方向必须呼应来源：从右侧划入的抽屉，退场也回到右侧。下方左栏是全部时长令牌的相对长度，右栏可以亲手对比同一元素的进与退。

M.4

编排：Stagger 实验室

30–60ms 是节奏，>80ms 是拖沓

顶尖与平庸最大的差距在编排：平庸做「一个个好看的动画」，顶尖做「一组动效如何协同成一个流畅的瞬间」。把强度预算押在一次精心编排的开场上，比每个按钮都抖一下高级得多。交错延迟太大显拖沓，太小看不出节奏。拖动滑杆亲自找那条界线。

Stagger调参后自动重播；进入视口时首播一次
建议区间 30–60ms。延迟随「距触发点的距离」衰减，比线性更自然；本典列表与网格入场统一取 38ms。
M.5

连续性：共享元素与 FLIP

不要 A 淡出 + B 淡入

当 A 变成 B（列表项 → 详情、缩略图 → 大图），不要「A 淡出 + B 淡入」，而要让共享元素连续位移与缩放过去。空间连续性让界面像真实物体，而不是一组屏幕。本站的实现分两层：跨页用原生 View Transitions（八章之间切换即是），页内用 FLIP（First–Last–Invert–Play，先测量前后位置，再用 transform 补差）。点击任一方块看 FLIP 展开。

M.6

滚动驱动叙事

触发式 vs 绑定式

滚动动效分两类：触发式进入视口播放一次（入场、数字滚动），绑定式把动画进度等同于滚动进度、可来回（视差、长镜头形变）。实现优先级从轻到重：原生 CSS 滚动驱动动画 → IntersectionObserver + class → 时间线库。本站全站揭示走原生 animation-timeline: view()，不支持的浏览器由 motion.js 用观察者回退，内容在任何情况下都不会因动效失败而不可见。

视口驱动在下方小窗内滚动
触发式：进入视口播放一次，适合入场与数字滚动。
绑定式（scrub）：动画进度 = 滚动进度，可来回，适合视差与长镜头形变。
节制视差：层间速度差要小，远景慢、近景快；过大会晕。
reduced-motion 下关闭视差与 scrub，保留终态与透明度变化。
只动 transform 与 opacity——这两个属性走合成器线程，是 60fps 的前提。
M.7

东方动效：間与运笔

轻 · 慢 · 含蓄

东方动效的内核是节奏与从容，不是某种特效。間（留拍）——动效在关键处停一拍再继续，是时间的留白；水的隐喻——ease-out 为主，有重力与惯性，时长偏长而不弹跳；云雾渐显——入场用 opacity + 轻微 blur + scale，如雾中显形，而非生硬位移；书法运笔——SVG 路径以 stroke-dashoffset 书写，配 elegant 缓动，收笔带一分回锋。下面是「永字八法」的抽象转译：八笔依次落墨，末了钤印。

M.8

状态编排：加载、反馈与浮层

空态与错态才是专业度的分水岭

骨架屏到内容不是「换一批 DOM」，而是一次编排：骨架的呼吸停止、内容按行 stagger 落位、布局不得抖动。浮层同理——模态自 spring 入场、遮罩同步渐显；Toast 从边缘滑入、3 秒后自行退场。三者用的是同一族缓动，所以像出自同一套物理规则。

M.9

无障碍契约与性能预算

reduced-motion 是硬要求，不是可选项

前庭功能障碍者会因大位移与视差产生真实的生理不适。prefers-reduced-motion: reduce 下我们不是全关，而是换成不引发不适的形式：关闭大位移、视差、自动播放与 scrub，保留透明度变化与终态。性能上目标 60fps（16.7ms/帧），只动 transform 与 opacity，filter: blur() 与大面积 backdrop-filter 有明确预算。

该做
  • 只动 transform 与 opacity；显隐用 opacity + visibility。
  • 退场时长取进场的 60–70%，方向呼应来源。
  • 一屏一处「点睛之动」，其余服务它。
  • reduced-motion 下保留终态与淡入，内容永不因动效失败而消失。
  • 入场动画的初始态由 JS 施加：无脚本时内容默认可见。
不该做
  • 动 width/height/top/left/margin——触发重排，卡顿之源。
  • 用 linear 做位移与淡入；用夸张 overshoot 显「活泼」。
  • 滥用 will-change：只在动画前临时加、动画后移除。
  • 为炫技上重武器：CSS 能做的 hover 不该用 3D 引擎。
  • 忽略退场动画与空 / 错状态——评审恰恰看这些边角。
本站的实现契约。全站揭示优先走原生 animation-timeline: view()；不支持时才由 motion.js 加 html.js-rv 并用 IntersectionObserver 补位。两条路径都以「内容默认可见」为基线——动效层挂了，站还是一份能读的文档。
