## 卷首 · 全典总纲

### 〇 核心哲学：从「美学四维」升维到「价值三维」

源裕兴品牌的核心哲学已由旧的「冲和 · 朴拙 · 开物 · 温润」四维美学，升维为「**守正 · 开物 · 共生**」三维价值体系。

| 维度 | 旧体系 | 新体系 | 变更说明 |
|------|--------|--------|---------|
| 核心哲学 | 冲和 · 朴拙 · 开物 · 温润（四维美学） | 守正 · 开物 · 共生（三维价值） | 从「设计应该长什么样」升维到「设计为什么而存在、往哪里去、和谁同行」 |
| 美学罗盘 | 四维罗盘（菱形十字） | 金三角罗盘（等边三角） | 结构重构，贯穿全典视觉系统 |
| 品牌人格 | 儒 × 侠 双核 | 儒 ←→ 侠 ⇄ 共生 三角 | 增加共生维度 |
| 设计誓约 | 五条（I–V） | 三条（精炼） | 以新哲学重构誓约文本 |

**三维价值深度释义**：

| 维度 | 英文 | 语义 | 品牌行为 | 设计系统中的体现 |
|------|------|------|---------|-----------------|
| **守正** | Preserving Integrity | 守根本、正本源。品牌不漂移，设计不媚俗。 | 品牌合规、视觉一致性、设计治理 | 设计令牌体系 · 品牌宪法 · 质量门禁 · 版本管控 |
| **开物** | Pioneering Innovation | 开新局、造新物。在经典框架中打开新的可能。 | 技术创新、东方 × 西方融合、前沿探索 | M3 动态色彩 · 太极流纹数字化 · AI 原生界面 · New Aesthetics |
| **共生** | Symbiotic Coexistence | 共生长、互成就。品牌与自然 / 社会 / 用户共同繁荣。 | 绿色设计、无障碍、利益相关者关怀、文化融合 | ESG · DEI · WCAG · 低碳设计 · 五实体生态协同 · 多语言 |

> **与旧体系的本质区别**：旧四维（冲和 / 朴拙 / 开物 / 温润）是**美学四维**，描述「设计应该长什么样」；新三维（守正 / 开物 / 共生）是**价值三维**，回答「设计为什么而存在、往哪里去、和谁同行」。
>
> 这不是否定过去——冲和（中道）融入守正、朴拙（本真）融入守正、温润（关怀）融入共生、开物继承延续。是**从美学升维到价值**。

### 一、三源合流

源裕兴品牌哲学根植于三大思想源头的合流：

| 源流 | 角色定位 | 核心贡献 |
|------|---------|---------|
| **马克思主义政治经济学** | 魂（Spirit） | 生产关系的洞察力、历史唯物主义的宏观视野、剩余价值论的经营理性 |
| **中华文明生成论** | 体（Body） | 阴阳相生、五行相济的生成哲学，书法笔墨的美学传统，士人风骨的价值观 |
| **精密社会工程学** | 法（Method） | Design Token 治理、组件化工程、数据驱动的可量化设计 |

> 三源不是并列装饰，而是「魂—体—法」的有机统一：政治经济学赋予品牌看透商业本质的魂，中华文明赋予品牌血肉丰满的体，精密工程赋予品牌可落地、可治理的法。

### 二、品牌人格三角

源裕兴的品牌人格是一个动态平衡的三角，而非单一标签：

| 人格 | 对应哲学 | 气质 | 边界（不可越） |
|------|---------|------|---------------|
| **儒**（Sage） | 守正 | 稳重 · 厚德 · 不迂腐 | 不因循守旧 |
| **侠**（Knight） | 开物 | 精进 · 开新 · 不冒进 | 不盲目标新 |
| **共生**（Symbiosis） | 共生 | 包容 · 生长 · 不孤立 | 不自我封闭 |

> 一句话：**儒侠双核，共生为脉**——每一个组件、每一个 Token 都必须通过「守正吗？开物吗？」的双重审视，并服务于「与谁共生」的终极追问。

### 三、设计誓约三条

> 这是源裕兴所有设计决策的**最终仲裁标准**。当工程规范与东方美学冲突时，设计誓约优先。

**誓约 I — 守正 · Know Thyself**
> 我承诺品牌不漂移、设计不媚俗。
> 每一个像素都忠诚于源裕兴的价值根基。
> 格物致知，守正出奇。

**誓约 II — 开物 · Make Things Happen**
> 我承诺在经典框架中打开新的可能。
> 不因循守旧，不盲目标新。
> 在 Geist 的纪律中注入东方百年字号的血。

**誓约 III — 共生 · Flourish Together**
> 我承诺设计首先服务于人，再服务于品牌，最后服务于自己。
> 品牌与自然共生、与社会共生、与用户共生。
> 绿色设计、无障碍、多语言、跨文化——不是附加项，而是出厂设置。

**核心故事线**：V36 是一部完整的宪法——它规定了品牌的一切原则、色彩、字体、间距，但它是一本「书」，需要人来阅读、理解、然后手动翻译成界面。V37 是一套可执行的组件库——同样的宪法原则现在长出了手与足。设计师不再「参考」规范，而是「调用」组件；工程师不再「翻译」Token，而是「引用」变量。这不是「推翻 V36」，而是「让 V36 活过来」。

### §03 设计系统总纲

**四极张力 → 三维张力**：

```
旧：文化（东方→西方）× 专业（克制→表达）
新：原则（守正 ←→ 开物）× 生态（独善 ←→ 共生）
```

**Pragmatic Futurism 定义更新**：

> 「以**守正**为根基——精密工程是骨架；以**开物**为利刃——中华文明是血肉；以**共生**为归旨——实用未来主义是神经。」

**核心十条（工艺判断准则）**：

1. 颜色只用 Token，不硬编码色值
2. 间距只用 4px 步进的 Token
3. 品牌紫（绛紫）仅用于 Primary 操作和重点元素
4. 不用纯黑 #000 / 纯白 #FFF——用 Ink 900 / Ink 50
5. 动效即叙事，不做无意义动效
6. 组件遵循 8 状态机
7. 每个交互元素可键盘操作
8. 正文对比度 ≥ 4.5:1（WCAG AA）
9. 暗色模式使用 data-color-scheme="dark"
10. 五实体主题通过 data-theme 切换，不漂移

**Ant Design 融合公式**：

$$ \text{V37 融合度} = 60\%\text{ AD 工程纪律} + 30\%\text{ 源裕兴文化基因} + 10\%\text{ Geist/M3 遗产} $$

- **60% AD 工程纪律**：Token 三层架构、Component Token、状态层、动效标准、可访问性规范
- **30% 源裕兴文化基因**：五实体色、宣纸墨色、儒侠人格、藤黄戒律、太极纹章
- **10% Geist/M3 遗产**：负字距（Swiss typography）、HCT 色彩空间、M3 Elevation

### §08 栅格系统（12 列宪法）

> 栅格是设计的宪法。12 列体系不可违——这是「守正」在布局层面的最高体现。栅格不是限制自由，而是给自由提供结构，就像五线谱不是限制音乐——是让音乐成为可能。

**五断点响应式栅格表**：

| 断点 | 屏幕宽度 | 列数 | 槽宽 (Gutter) | 边距 (Margin) | 典型设备 |
|------|---------|:---:|:------------:|:------------:|---------|
| xs | < 600px | 4 | 16px | 16px | 手机竖屏 |
| sm | 600–904px | 8 | 16px | 24px | 手机横屏 / 小平板 |
| md | 905–1239px | 12 | 24px | 32px | 平板 / 小笔记本 |
| lg | 1240–1439px | 12 | 24px | 40px | 桌面显示器 |
| xl | ≥ 1440px | 12 | 24px | auto（max 1200px 内容区） | 大屏 / 超宽 |

**栅格嵌套规则**：

1. 列中可嵌套 12 列（任何 `.col-N` 内部可再次创建 12 列子栅格）
2. 嵌套深度 ≤ 3 层（超过提示布局过于复杂）
3. 嵌套时 gutter 继承父级
4. 不嵌套纯定位元素（绝对定位元素不参与栅格计算）

**栅格与黄金分割**：

| 应用场景 | 比例 | 示例 |
|---------|:----:|------|
| 主内容:侧栏 | ≈ 8:5 | `col-8` + `col-4` → 8/4 = 2 ≈ 1.618 ✅ |
| 更精确布局 | ≈ 7:5 | `col-7` + `col-5` → 1.4 |
| Hero 文字:留白 | ≈ 1:1.6 | 标题占 38%，留白占 62% |
| 卡片宽高比 | 1:1.618 | 横向卡片 |

> 这些比例是参考，不是教条。12 列栅格是第一宪法，黄金分割是第二参考。当两者冲突时，12 列栅格优先。

**栅格破坏规则（Grid Break）**：Hero 全屏插画 `grid-break--hero`、数据大屏 `grid-break--dashboard`、全屏图像 `grid-break--full-bleed`、装饰性溢出 `grid-break--bleed-right`——可突破栅格但需显式标注。

**Odoo 18 栅格适配**：Odoo 18 使用 Bootstrap 4 栅格（也是 12 列），天然兼容。SCSS 覆盖 `$grid-gutter-width: 24px`、`$container-max-widths` 对齐源裕兴断点。

### §17 交互模式库

| Top App Bar | 全断点 | 3–5 | 守正——经典不犯错 |
| Nav Rail（侧轨） | md+ | 4–7 | 守正——侧轨是最经典的桌面导航 |
| Nav Drawer（抽屉） | xs/sm | 4–10 | 共生——移动端优先 |
| Bottom Nav Bar | xs/sm | 3–5 | 共生——拇指友好 |
| Breadcrumbs（面包屑） | md+ | 不限 | 守正——位置不失 |
| Tabs | 全断点 | 2–6 | 开物——横向扩展 |

**表单验证时机**（源裕兴推荐**失焦验证**）：

| 验证方式 | 适用场景 | 优点 | 缺点 |
|---------|---------|------|------|
| 提交时验证 | 简短表单（≤5 字段） | 不打断输入 | 提交后才发现错误 |
| 失焦验证 ★ | 中等表单（6–12 字段） | 即时反馈 | 可能打断专注 |
| 实时验证 | 用户名 / 密码强度 / 搜索建议 | 零等待 | 过早报错干扰 |

**批量操作确认策略**：

| 操作类型 | 确认方式 | 说明 |
|---------|---------|------|
| 批量删除 | 模态弹窗确认 | 不可逆操作，必须二次确认 |
| 批量移动 | 内联选择器 | 低风险，流畅不打断 |
| 批量导出 | 直接执行 + Toast | 无风险，即时反馈 |
| 批量审批 | 快速确认条 | 中等风险，轻量确认 |

**加载策略矩阵**：

| 加载模式 | 适用场景 | 用户感知 |
|---------|---------|---------|
| 骨架屏 (Skeleton) | 页面首次加载 / 列表刷新 | 「内容即将出现」 |
| 进度条 (Progress Bar) | 文件上传 / 数据导入 | 「还需等待 X 秒」 |
| 旋转器 (Spinner) | 短操作（<3 秒） | 「正在处理」 |
| 乐观更新 (Optimistic) | 点赞 / 收藏 / 已读 | 「操作已完成」 |
| 渐进式加载 (Progressive) | 长列表 / 图片网格 | 「越滚越多」 |
| 流式输出 (Streaming) | AI 对话 / 报告生成 | 「边生成边看」 |

**超时降级**：<1 秒无需指示；1–3 秒旋转器；3–10 秒进度条 + 预计剩余时间；>10 秒进度条 + 后台处理 + 通知；>30 秒错误提示 + 重试按钮。

**快捷键**：全局搜索 `⌘K` · 保存 `⌘S` · 撤销 `⌘Z` · 重做 `⌘⇧Z` · 新建 `⌘N` · 关闭弹窗 `Escape` · 提交表单 `⌘Enter`。

> 每一个交互，都是品牌与用户的一次握手。失焦验证而非实时打扰——让用户在专注和反馈之间找到平衡；加载不是「让用户等」，而是「陪用户等」——骨架屏的 shimmer 动画给了等待以温度。好的交互不是让用户完成任务，而是让用户感觉被一个体贴的伙伴陪伴着。这就是共生。

### §18 UX 方法与流程

**设计思维五步法（与三维价值对齐）**：

```
Empathize  →  Define  →  Ideate  →  Prototype  →  Test
   共情          定义         构思         原型         测试
    │             │            │            │            │
   共生          守正         开物         开物         共生
```

| 步骤 | 核心问题 | 交付物 | 哲学映射 |
|------|---------|--------|---------|
| Empathize | 用户真正的痛点？ | 用户需求洞察报告 | 共生 |
| Define | 核心问题是什么？ | 问题定义文档 | 守正 |
| Ideate | 有哪些解决方案？ | 创意方案矩阵 | 开物 |
| Prototype | 如何快速验证？ | 可交互原型 | 开物 |
| Test | 用户真的需要吗？ | 测试报告 + 迭代清单 | 共生 |

**用户研究方法 2×2 矩阵**（定量↔定性 × 行为↔态度）：A/B 测试 / 点击流 / 热力图（定量·行为）· NPS / 问卷（定量·态度）· 可用性测试 / 眼动追踪（定性·行为）· 用户访谈 / 焦点小组 / 日记研究（定性·态度）。

**五实体典型 Persona**：

| 实体 | Persona | 核心需求 | 关键痛点 |
|------|---------|---------|---------|
| STG | 集团 CFO 李总 | 全局经营看板、风险预警 | 数据分散在多个系统 |
| STE | 工厂经理 王工 | CFB 锅炉实时监控、碳配额管理 | 操作界面复杂、响应慢 |
| STI | 贸易经理 陈先生 | 报关状态追踪、汇率预警 | 多平台切换、语言障碍 |
| STH | 产品经理 张博士 | GMP 合规文档管理、临床数据 | 法规更新频繁、文档版本混乱 |
| EDU | 教务主任 刘老师 | 学生成长档案、家校沟通 | 数据录入繁琐、家长端体验差 |

**用户旅程地图**：As-Is（现状）→ To-Be（理想）两步法，六阶段（意识 → 考虑 → 决策 → 使用 → 支持 → 留存），对应指标（访问量 / 转化率 / DAU / 工单量 / 续费率 / NPS）。

**版本控制策略**：Patch（修复）/ Minor（新增）/ Major（破坏性变更）三级语义化版本。

> 设计思维的第一步是共情——站到用户的位置上。Persona 模板中的「品牌契合度」维度让品牌哲学穿透用户研究，而不只是人口统计标签。Figma Token 同步管线是开物——用工程自动化替代手工复制粘贴；版本策略是守正——每一次变更都可追溯、可回滚。

### §20 无障碍与包容性设计（WCAG 2.2 AA）

**四大原则合规清单**：

**可感知（Perceivable）**：非文本内容有文本替代（alt / aria-label）；预录视频配字幕；语义 HTML（nav / main / h1–h6）；DOM 顺序 = 视觉顺序；色彩不作为唯一信息载体；普通文本对比度 ≥ 4.5:1；支持 200% 缩放；UI 组件边界 ≥ 3:1。

**可操作（Operable）**：全键盘操作（Tab / Shift+Tab / Enter / Escape）；无键盘陷阱（模态弹窗 Escape 可关闭，焦点回到触发元素）；跳过块 Skip Link；焦点可见（2px 绛紫外框）；触摸目标 ≥ 44×44px。

**可理解（Understandable）**：`<html lang="zh-CN">`；全局导航位置一致；表单错误用文字 + 图标 + 颜色三重标识；所有输入框有 `<label>`；删除操作二次确认。

**健壮（Robust）**：HTML 通过 W3C 验证；自定义组件使用 ARIA（role="tablist" 等）。

**色彩对比度速查表（五实体色 × Ink 底色）**：

| 实体色 | 白底 (Ink 50) | 深底 (Ink 800) |
|--------|:---:|:---:|
| 绛紫 #851EA3 | ✅ 7.4:1 | ✅ 4.5:1 (大) |
| 苍木绿 #196B42 | ✅ 7.2:1 | ✅ 4.2:1 (大) |
| 深空蓝 #1E4082 | ✅ 9.1:1 | ✅ 5.6:1 |
| 沧浪青 #208F9B | ✅ 4.8:1 | ⚠️ 3.2:1* |
| 朱砂红 #B81E1E | ✅ 6.8:1 | ✅ 4.2:1 (大) |

> ⚠️ 沧浪青在浅色背景上对比度偏低。建议：正文用沧浪青时字号 ≥ 18px Bold，或使用加深变体（L 值下调 0.05 → oklch(0.47 0.08 200)）用于小号文字。

**屏幕阅读器测试矩阵**：macOS VoiceOver（每次发布）· Windows NVDA（每次发布）· iOS VoiceOver（每次发布）· Android TalkBack（每季度）。

**认知无障碍**：正文 14–16px，行高 1.5–1.8；同类操作全站一致；不可逆操作二次确认；多步骤流程显示进度；不依赖记忆。

> 无障碍不是附加项，是出厂设置。WCAG 2.2 AA 的每一条准则都在回答同一个问题：所有人都能平等地使用源裕兴的产品吗？这是共生——设计首先服务于人，所有人。这是守正——WCAG AA 是品牌的底线，不可妥协。

### §21 AI 原生界面设计

**Agentic UX 五原则**：

| # | 原则 | 说明 |
|---|------|------|
| 1 | 意图优先 | AI 先理解用户意图，而非等用户下达精确指令 |
| 2 | 渐进式披露 | 先给结论，再给依据，最后给原始数据 |
| 3 | 人在回路 | AI 可建议、可执行，但最终决策权归人 |
| 4 | 可解释性 | AI 的每一个决策都必须能回答「为什么」 |
| 5 | 优雅降级 | AI 失败时，用户不能被困住 |

**置信度三级视觉编码**：

| 置信度 | 视觉编码 | 颜色 | 文案模板 |
|:---:|---------|------|---------|
| 高 ≥ 85% | 实心 · 稳定 | 苍木绿 | 「高度可信」+ 不标注百分比 |
| 中 60–84% | 半透明 · 提示 | 金色 | 「置信度 75%」+「建议人工复核」 |
| 低 < 60% | 虚线 · 警告 | 朱砂红 | 「置信度较低（42%），仅供参考」 |

**流式输出三模式**：逐字（边想边说，AI 对话）· 逐句（边说边停，报告生成）· 批量（一次性交付，数据分析）。

**人机协作三模式**：Copilot（AI 建议，人决策）· Autopilot（AI 执行，人监督）· Advisor（AI 顾问，人学习）。

**模式切换规则**：Copilot → Autopilot（置信度持续 >90% + 用户连续确认 5 次）；Autopilot → Copilot（置信度 <85% 或用户接管）。

> AI 是源裕兴「开物」精神在数字时代的最前沿。Agentic UX 的五原则、流式输出的三重节奏、置信度的三级视觉编码——这些不是在追 AI 的潮流，而是在定义 AI 时代的设计语言。但 AI 必须守正——人在回路（最终决策权不交给算法）、可解释性（每个推断有据可查）、优雅降级（AI 可以失败，但用户不能被困）。在算法的效率与人的尊严之间，源裕兴永远选择后者。

## Part 06 · 技术规范（§25–§28）

### §25 设计令牌技术规范

**三层架构**：

```
Layer 1: Primitive (--c-ref-*)     → 86 原始色值，不可直接用于组件
Layer 2: Semantic  (--c-*)         → 142 语义角色，data-theme 动态映射
Layer 3: Component (--cmp-*)       → 258 组件 Token，指向 Semantic
```

> CSS 自定义属性是品牌在代码中的 DNA。不可硬编码，不可绕过。M3 23 色角色 → DTCG Token → Style Dictionary → CSS/SCSS/NPM——这条管线不是技术选择，是品牌宪法在工程层面的「单一可信源」（守正）。

### §26 前端开发规范

**项目目录结构标准**：`index.html` + `parts/`（part-01~10 + icons + components + applications）+ `css/`（shared / icons-tokens / illustrations / dark）+ `js/`（shared / icon-controller）+ `icons/`（sprite / taiji / chart）+ `illustrations/` + `assets/` + `docs/` + `README.md`。

**CSS 架构（ITCSS 分层）**：

```
Layer 1: Settings  — CSS 自定义属性（Token）
Layer 2: Tools     — Mixins / 工具类
Layer 3: Generic   — Reset / normalize / box-sizing
Layer 4: Elements  — 裸 HTML 元素样式（h1-h6, p, a, img）
Layer 5: Objects   — 布局类（.grid, .container, .page）
Layer 6: Components— BEM 组件（.nav, .hero, .card, .phi-anchor）
Layer 7: Utilities — 辅助类（.u-text--muted, .u-mt-s4）
```

**关键规则**：禁止 `!important`（除非覆盖第三方库）；禁止 ID 选择器用于样式；选择器深度 ≤ 3 层；禁止硬编码色值；间距只用 Token。

**命名规范**：HTML/CSS 文件 kebab-case；CSS 类名 BEM（`.nav__link--active`）；CSS 变量 `--kebab-case`；JS 函数 camelCase；JS 常量 UPPER_SNAKE。

**Git 工作流**：main（生产）→ develop（开发主干）→ feature/* + hotfix/*；Commit Message `<type>(<scope>): <subject>`。

**性能预算**：Lighthouse ≥ 95 · FCP < 1.5s · LCP < 2.5s · TBT < 200ms · CLS < 0.1 · 页面总大小 < 500KB · CSS < 50KB（压缩后）。

> 代码是品牌在浏览器中的终极化身。禁止硬编码色值、禁止 `!important`、间距只用 Token——每一条规则都在回答同一个问题：你能从代码中读出品牌吗？这是守正。

### §27 设计工具与工作流

**Figma 文件结构**：品牌宪法（哲学 / 资产 / 栅格）→ Design Tokens（Colors / Typography / Spacing / Shapes / Motion）→ Components（Button / Card / Nav / Form / Dialog / Data Display）→ Screens（五实体）→ Prototypes。

**设计 Token 同步管线**：Figma Variables → tokens.json（DTCG 规范）→ Style Dictionary Build → CSS / SCSS / JSON / NPM（@sinotao/design-tokens）。

**CI/CD 自动同步**：Figma 变量变更 → Webhook 触发 → GitHub Actions 运行 Style Dictionary → 生成新版 tokens → 自动 PR → 人工审核 → 合并 → 自动发布 NPM。

**组件库版本管理**：MAJOR.MINOR.PATCH 语义化版本 + 变更日志（Added / Changed / Deprecated / Fixed）。

**多平台交付通道**：Figma Dev Mode · Storybook · Zeroheight · NPM · 全典 HTML 静态站点。

**设计评审四阶门禁**：自审（WCAG / 五实体切换 / 响应式）→ 同行审（BEM / Token 引用）→ 跨职能审（前端 / Odoo / 内容）→ 品牌审（哲学对齐 / 五实体差异化 / 品牌委员会批准）。

> 工具服务于流程，流程服务于品牌宪法。工具可以换，但 Token 的单一可信源不可换。这是守正。

### §28 设计-开发交接

**交付清单六维度**：设计稿（Figma）· Design Token · 组件（状态矩阵 + 响应式）· 动效（缓动 + 时长）· 无障碍（WCAG + 键盘 + 屏幕阅读器）· 测试用例（正常 + 边界 + 五实体切换）。

**交接会议议程（标准 45 分钟）**：设计意图说明 → 设计稿走查 → 技术可行性确认 → 边界情况讨论 → 任务拆解估时 → 确认清单 + 设定 Design QA。

**Design QA 检查项**：像素对比（偏差 < 2px）· 色彩（100% Token 引用）· 间距（100% 4px 步进）· 字体（完全匹配）· 响应式（5 断点）· 动效（视觉匹配）· 无障碍（WCAG 全通过）· 五实体（主题切换无异常）。

**Odoo 18 特化交接**：QWeb 模板标记（`t-name="sinotao.Dashboard"`）· SCSS 变量覆盖清单（`$o-company-primary-color` → `var(--sino-entity-ste)`）· OWL 组件映射（Button / Card / Nav Rail / Data Table / Dashboard）。

> 交接不是「设计做完丢给开发」，而是「设计意图完整、无误、无损地传递到代码」。交付清单的六维度确保没有任何设计决策在传递中遗失。这是守正——守设计之正，守品牌之正，守工程之正。

## Part 07 · 声音感官（§29–§31）

### §29 声音品牌

**品牌声纹参数**：音高 / 节奏 / 音色三维调校的品牌声音签名。通知音不是随意的「叮咚」，而是经过调校的品牌声纹。静音模式下的触觉反馈——声音与沉默的共生。

### §30 服务设计

**服务蓝图三层模型**：

```
物理证据    │ 网站  │ APP  │ 邮件  │ 电话  │ 会议室 │ 报表  │
客户行为    │ 发现 → 了解 → 试用 → 购买 → 使用 → 续费     │
前台（可见）│ 官网  │ Demo │ 注册  │ 支付  │ 工单  │ NPS  │
后台（不可见）│ SEO  │ 销售  │ 开通  │ 发票  │ 支持  │ 分析 │
支持流程    │ IT基础设施 · HR · 法务 · 财务 · 品牌委员会   │
```

**触点矩阵（五实体 × 六旅程阶段）**：从 STG 的「行业峰会 → 官网白皮书 → 经营看板 Demo → 合同 → 经营仪表盘 → 年度审计」到 EDU 的「教育局官网 → 招生简章 → 试听课 → 报名缴费 → 家校通 → 学期评估」，每实体一条完整旅程。

**服务指标**：首次响应时间 < 1 小时 · CSAT ≥ 90% · NPS ≥ 50 · 自助解决率 ≥ 60% · 触点一致性 ≥ 95%。

> 服务不是解决问题，是建立关系。客户从 STE 能源切换到 STI 贸易时，感受到的不是「换了一家公司」，而是「同一个品牌，不同的专家」。这是共生。

### §31 客户旅程

六阶段 As-Is → To-Be 两步法——不是「我们想让客户走的路」，而是「客户实际上在走的路」和「他们想走的路」。走客户的路，而不是让客户走你的路（共生）。

## Part 08 · 可持续、伦理与责任（§32–§34）

### §32 可持续设计

低碳设计 checklist——从服务器能效到印刷油墨的 VOC 含量——像素层面的碳中和。绿色设计不是品牌的面子工程，是品牌的里子工程（共生）。

### §33 ESG

**反漂绿（Anti-Greenwashing）守则**：品牌不夸大环保承诺，不用绿色滤镜粉饰灰色操作（守正）。ESG 品牌传达让利益相关者看到真实的、可验证的可持续行动（共生）。

### §34 DEI 与包容性品牌

**包容性视觉设计原则**：多元代表（插画 / 摄影展示不同年龄 / 性别 / 肤色 / 残障状态）· 避免刻板印象 · 文化敏感 · 年龄友好（最小字号 ≥ 14px）· 性别中立 · 多语言平等。

**WCAG 2.2 新增准则专项**：2.4.11 焦点不遮挡（AA）· 2.5.7 拖拽动作（AA）· 2.5.8 触摸目标（AA）· 3.2.6 一致的帮助（A）· 3.3.7 可访问的认证（AA）。

**移动端无障碍增强**：单手操作（关键操作在拇指热区）· 横屏支持 · `prefers-reduced-motion` 减少动效 · `prefers-contrast` 高对比度。

**包容性插画规范（人物多样性矩阵）**：性别 / 年龄 / 种族肤色 / 残障 / 体型 / 职业——每幅包含人物的插画需通过六维度检查。

**DEI 度量指标**：插画人物多样性评分 ≥ 80% · WCAG 合规率 100% · 多语言覆盖率 100% · 屏幕阅读器兼容性三平台 · 键盘可操作率 100%。

> 多元是世界的真相，公平是文明的底线，包容是品牌的选择。WCAG 2.2 AA 是地板，不是天花板。这是共生——品牌与真实世界中所有人的共生。这是守正——DEI 不是附加项，是出厂设置。

**四维 KPI 树**：覆盖率 · 复用率 · 效率 · 满意度。度量不是为了证明设计系统「很棒」，是为了发现哪里「还不够好」（守正）。

### §37 品牌演进、重塑与危机

**品牌生命周期模型**：新生期 → 成长期 → 成熟期 → 焕新期（或衰退 → 重生）。源裕兴当前处于**成长期**，适合「进攻型建设」。
